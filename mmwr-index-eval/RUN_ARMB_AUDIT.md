# Arm-B audit (instructions for the orchestrating Claude Code session)

**Question.** In arm B, Opus reviewed Haiku's record and changed only what it disagreed with. The merged record inherits every other Haiku value, and the pilot scored only articles where the two records disagreed. So errors that Haiku made and the review missed may be hidden. This audit gives a sample of arm-B articles an **independent, blind Opus full read** and compares it with the merged record. Run it on **brief v3**, the brief that produced the merged records, before any brief changes.

**Scope and permissions.** Work only inside `mmwr-index-eval/`. Do not modify `packets/`, `examples/`, the briefs, the pilot outputs (`out/haiku/`, `out/opus/`, `out/opus_review/`, `out/merged/`, `adj_packet/`, `adjudication/`, `adj_mapping.json`, `reports/*` from the pilot) or the existing tools. The owner has permitted one new tool, `tools/audit.py`, which writes only audit-specific paths. If something else is broken, stop and report.

**Sample** (already generated by `python3 tools/audit.py sample`, deterministic): `audit_sample.tsv` and `audit_batches.json`. 24 arm-B articles in 7 batches:
- all 18 arm-B articles where the pilot found **no** disagreement (13 from 2023–24, 5 from 1999–2001). They were never adjudicated, so this is where hidden errors would be;
- 6 arm-B articles that **were** disputed and adjudicated (5 R, 1 O), as a calibration check against the pilot's adjudication.

**Budget guard.** Expected total about 1.5M tokens in the harness's per-agent metric (7 readers and 5 adjudicators). If the logged total passes **2.5M**, stop and report.

## Steps
1. **Audit read.** For each batch in `audit_batches.json`, spawn one reader (model `opus`) with the reader prompt below. Run all 7 at once. After each one, append a row to `audit_run_log.tsv` (same columns as `run_log.tsv`: batch, role `audit-judgment`, model, status `ok n/n`, subagent tokens, tool uses, duration, refusals, notes). Check that every record's `reader.model` is a 5.5 Opus model id. If not, stop and report.
2. **Check.** Run `python3 tools/validate.py out/opus_audit/*.json`. Re-run any failing article once, alone. If it fails again, leave it and note it.
3. **Compare.** Run `python3 tools/audit.py compare`. It writes `adj_packet_audit/`, `audit_mapping.json` and `reports/audit_agreement.tsv`.
4. **Adjudicate all 24 articles,** including those where the two records fully agree: the point is to find errors both share. Use 5 Opus adjudicators, taking the articles in `audit_sample.tsv` order in groups of 5, 5, 5, 5, 4, with the adjudicator prompt below. Log each one in `audit_run_log.tsv` (role `audit-adjudicator`).
5. **Score.** Run `python3 tools/audit.py score`. It writes `reports/audit_scores.tsv` and `reports/audit_brief_issues.md`.
6. **Report.** Write `reports/AUDIT_REPORT.md`:
   - models used; articles done, refused or failed; tokens and time per article (from `audit_run_log.tsv`);
   - **hidden-error rate:** the merged record's field error rate on the 18 previously undisputed articles, overall and on the high-value fields (procedures and regression families, study design, comparison, equity level and dimensions), with each hidden error listed (article, field, what was wrong);
   - the independent audit reader's error rate on the same articles, as the benchmark (compare also with arm A's full Opus reader in the pilot: 1.4%);
   - **calibration:** on the 6 disputed articles, whether the audit adjudication agrees with the pilot's adjudication about the merged record (compare `adjudication_audit/<id>.json` with `adjudication/<id>.json` here, as the orchestrator; adjudicators must not see the pilot's);
   - **how far review moved Haiku:** `haiku_vs_audit` vs `merged_vs_audit` disagreements in `reports/audit_agreement.tsv`;
   - a recommendation on arm B, under the decision rule below, with the sample-size caveat (18 articles is about 490 field judgments; it detects large differences only);
   - recurring `brief_issues` not already in `reports/brief_issues.md`; anything that went wrong.
7. **Commit** everything under `mmwr-index-eval/` to the working branch with a short message. Do not merge to the main branch.

**Decision rule (proposed by the owner's assistant; the owner may revise).** Arm B is acceptable for the judgment record if, on the undisputed articles, the merged record's error rate on the high-value fields is no worse than the independent audit reader's by more than about 2 percentage points, and no hidden error changes an equity level by 2 or more or misses a primary procedure. Otherwise, arm B needs a targeted fix (e.g. a mandatory full re-read of named fields) or should not be used.

**Refusals.** As in the pilot: record, retry once alone, then leave it and report it. Never edit a reader's or adjudicator's record yourself.

**Scratch files.** Parallel agents in the pilot overwrote each other's helper scripts in a shared scratch folder. Give each agent its own subfolder of the session scratchpad, named after its batch or group, and substitute that path for `<SCRATCH>` below.
